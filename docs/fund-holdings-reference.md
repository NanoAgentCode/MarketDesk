# 基金持仓参考

从 1.9.0 起，F 基金在原有刷新任务中查询披露股票持仓，并尝试计算人民币口径的累计贡献和参考净值。基础计算在安卓本地完成，无账号、服务器或额外后台任务。

## 使用方式

- 主列表和小组件继续显示平台估值或已公布净值。取得持仓贡献后，小组件的简短标记为“参考”，完整数字见 App 的“更多”。
- “更多”只增加简短摘要：参考净值、累计贡献、基准净值日期、披露与可计算权重、持仓报告期以及价格/汇率日期。
- 摘要旁的“持仓明细”按钮打开逐股计算依据。没有新增页面、表格列或设置开关。
- “查询其他主动 / 联接基金”也查询持仓参考。没有直接股票持仓的联接基金仍展示净值或平台估值，不用目标 ETF 或指数替代。

## 数据与计算

1. `FundValuationLast`：平台估值 GSZ/GZTIME 及已公布 NAV/PDATE，保留原有数据类型与优先级。
2. `FundMNInverstPosition`：股票代码 GPDM、名称 GPJC、市场 NEWTEXCH、占净值比例 JZBL 和报告期 Expansion。
3. 东方财富前复权日线：从 NAV 日期前七天开始查询，以 NAV 日期当天或此前最近的有效收盘价作为基准。最新批量延迟行情可用时更新末端价格；否则保留有日期标记的日线参考。
4. 东方财富历史链路失败时，尝试 Yahoo 相同股票历史与最新常规行情，使用调整价格避免拆股被当作亏损。
5. Yahoo 外汇历史和最新参考：USD/CNY、HKD/CNY，以及已核验日韩股票所需 KRW/CNY、JPY/CNY。汇率是市场参考价，并非基金管理人的实际结算价。

累计资产回报 = 当前参考价 / 基准参考价 - 1。

外币资产人民币回报 = (1 + 资产累计回报) × (1 + 同期汇率回报) - 1。

股票贡献（百分点）= 披露占净值权重（比例）× 人民币累计回报（百分数）。例如占净值 40% 的股票上涨 10%，已知贡献为 4 个百分点。

参考净值 = 已公布 NAV × (1 + 已披露股票贡献 / 100)。该模型固定披露权重，并假设未披露仓位价值不变。它不是实际基金全持仓估值，累计贡献也不是基金当日涨跌幅。基金费用、管理人调仓、现金流、未披露资产和价格调整口径均可能产生偏差。

只有全部披露的有效股票都有可匹配的价格和必要汇率时，才生成参考净值；存在缺失时仅显示成功匹配部分的贡献及缺失原因。零涨跌是有效数据，不能当成取数失败。

## 缓存、错误与时间

- 成功持仓缓存一天；股价历史、最新行情、汇率和失败结果缓存最多 60 秒。
- 全 App 共用四个取数线程。同一标的和 NAV 日期的在途请求由不同基金复用，不为每只基金复制行情请求。
- 持仓参考单次整体等待最多 40 秒；超时不使已公布净值或平台估值失效。
- 保留原始股票时间和市场日期。日线只标记为日线参考，不用请求时间冒充行情时间。
- NAV 早于当前日期 45 天、报告期早于当前日期 190 天、历史基准距 NAV 日期超过七天、末端数据日期早于当前日期 14 天，均停止相应计算。未来或无效日期也不参与计算。
- 多市场的参考价与汇率可能不是同一时刻，摘要列出日期，逐股明细保留时间；不能当作同步实时净值。

## 验证

单元测试覆盖部分持仓权重、缺失行情/汇率、0% 涨跌、累计回报、非交易日基准、拆股调整、不同市场/币种、未来和过旧数据、缓存共享/重试以及主列表数据不被参考值覆盖。

开发机实际 Java 请求链路已查询 017436、100055、000001、005827，四只均取得参考净值；100055 的十只披露股票全部匹配，包括 A/H/美股及上述日韩标的。原始结果保存在 `output/verification/fund-reference/live-results.json`。这些结果只证明当次取数与计算可用，不证明连续交易日精度，也不替代手机网络验证。

精度验收需连续保存 10–20 个交易日的收盘参考值，在官方 NAV 公布后按净值所属日期配对，比较净值相对误差、收益误差、方向一致率和数据可用率。此版本尚无可信的实测精度承诺。
